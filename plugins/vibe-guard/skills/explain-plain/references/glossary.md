# 白话术语表

解释概念时用这里的类比，全项目保持一致的说法。

| 术语 | 一句话白话 | 类比 |
|---|---|---|
| 前端 | 用户在浏览器 / 手机上看到和点的那部分 | 餐厅的外场、菜单 |
| 后端 | 在服务器上跑、用户看不到的那部分，负责存数据、跟别的服务打交道 | 餐厅的厨房 |
| API | 两个程序之间约好的「点菜方式」 | 服务员接单的格式 |
| API key | 调用别人服务时的身份凭证，等于付费账号的密码 | 会员卡 + 密码 |
| 数据库 | 有结构、能长期保存数据的地方 | 共享的 Excel 表 |
| 数据表 / 栏位 | 数据库里的一张表 / 表里的一列 | 一个工作表 / 一列 |
| 本地存储（localStorage） | 存在这台浏览器里的数据，换设备就看不到 | 便利贴贴在自己电脑上 |
| 环境变量 / .env | 放在代码外面的设置，用来藏密钥、区分测试和正式环境 | 保险箱，代码只知道「去保险箱拿」 |
| .gitignore | 告诉 git「这些文件不要存档、不要上传」的清单 | 寄快递时的「违禁品清单」 |
| git / 提交（commit） | 给整个项目拍快照的存档系统 / 一次快照 | 游戏存档 |
| 分支（branch） | 从某个存档分出去的平行世界，可以放心乱试 | 另存新档 |
| 推送（push）/ 拉取（pull） | 把存档上传到 GitHub / 从 GitHub 下载 | 同步到云端 |
| 依赖 / 包（package） | 别人写好、你的项目拿来用的零件 | 预制件 |
| npm install / pip install | 把项目需要的零件下载下来 | 照材料清单去采购 |
| 部署（deploy） | 把项目放到网上，让别人能打开 | 开店营业 |
| 域名 / HTTPS | 网址 / 加密连线（网址前面的锁） | 门牌 / 防窃听的信封 |
| 服务器 | 一台 24 小时开着、帮你跑后端的电脑 | 租来的厨房 |
| 端口（port） | 同一台电脑上不同程序的门牌号，例如 3000 | 大楼里的房间号 |
| localhost | 你自己这台电脑 | 自己家 |
| 日志（log） | 程序运行时写下的流水账，出错时用来查原因 | 行车记录仪 |
| 报错 / 异常 | 程序遇到做不下去的情况时发出的通知 | 仪表板警示灯 |
| 测试 | 自动检查功能是否还正常的小程序 | 出厂检验 |
| 登录 / 验证（auth） | 确认「你是谁」 | 刷门禁卡 |
| 权限 / RLS | 确认「你能看、能改哪些东西」 | 门禁卡能开哪几扇门 |
| 迁移（migration） | 修改数据库表结构的有记录的步骤 | 装修施工单 |
| 缓存 | 为了快，暂存一份之前的结果；有时会导致看到旧内容 | 记在脑子里的答案 |
| 技术债 | 为了快而走的捷径，以后要花更多时间还 | 信用卡先刷 |
| 重构 | 不改功能，只把代码整理得更好改 | 整理房间 |
| 框架（React / Next.js / Vue 等） | 一套盖房子的标准工法 + 工具 | 预制房屋系统 |
