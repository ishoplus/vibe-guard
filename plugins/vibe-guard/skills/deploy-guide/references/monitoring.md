# 上线后的监控

目标：**出事时先由系统通知你，而不是由用户来告诉你**。

> 以下服务的免费额度和界面会变，推荐前请在官网确认。

| 监控什么 | 用什么 | 最低设置 |
|---|---|---|
| 程序报错 | Sentry（有免费方案），或托管平台自带的错误 / 日志功能 | 前端和后端都接上；有新错误时发邮件 |
| 网站是不是还开着 | UptimeRobot、Better Stack 等存活监控（有免费方案） | 每 5 分钟检查一次正式网址首页；打不开时发邮件或手机通知 |
| 费用 | 各服务的预算告警（见 safe-start 的 budget-alerts） | 所有付费服务都设好；AI API 设硬上限 |
| 数据库 | 数据库平台后台 | 知道去哪里看用量和备份状态 |

## 上线后第一周
- 每天看一次：错误通知、费用、存活监控
- 有真实用户反馈问题时，先看错误监控里有没有对应的报错，再走 debug-rescue

## 日常维护（每月一次就好）
- 跑一次 ship-check（`--online` 会查依赖有没有新漏洞）
- 看一眼各服务的费用趋势
- 确认备份还在正常进行
- 这些可以请 AI 设成定期提醒
