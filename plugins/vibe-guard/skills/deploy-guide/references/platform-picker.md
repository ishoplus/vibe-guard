# 选托管平台

> 平台的免费额度、价格、界面都会变。以下是**选型方向**；推荐前请在对方官网确认当下的免费额度与超额规则，并如实告诉用户「超出后是停服还是自动扣款」。

## 按项目类型

| 项目是什么 | 推荐方向 | 说明 |
|---|---|---|
| 纯静态网页（HTML/CSS/JS、Vite/React 打包后的网站） | Vercel、Netlify、Cloudflare Pages、GitHub Pages | 最简单，基本免费；连 GitHub 就能自动部署 |
| Next.js 网站 | Vercel | Next.js 官方团队的平台，兼容性最好 |
| 需要一直运行的后端（Node / Python 服务、定时任务、WebSocket） | Railway、Render、Fly.io | 按运行时间或资源计费，要设用量上限 |
| 数据库 | Supabase、Neon（Postgres）；Firebase（文档型） | 选有自动备份的方案；正式和测试各开一个 project |
| 登录 | 用数据库平台自带的（Supabase Auth、Firebase Auth）或 Clerk | 不要自己存密码 |

原则：**能用「静态网站 + 托管数据库」解决的，就不要引入一直运行的后端**。组件越少，出事的地方越少、费用越可控。

## 按用户在哪里

| 用户主要在 | 取舍 |
|---|---|
| 中国大陆以外 | 上表的平台都可以 |
| 中国大陆 | 境外平台（Vercel、Netlify 等）在大陆访问**可能慢或不稳定**，有时部分地区打不开；换成国内云（阿里云、腾讯云等）访问快，但**用自己的域名对外提供网站服务需要先做 ICP 备案**，流程要一段时间。只给自己或少数人用、能接受偶尔慢的，可以先用境外平台 |

这个取舍要讲给用户听，由用户决定；不要默默替用户选。

## 为什么不推荐新手自己租服务器（VPS）

自己租一台 Linux 服务器看起来便宜又自由，但同时接下了这些工作：系统安全更新、防火墙、SSH 登录安全、HTTPS 证书续期、进程挂了自动重启、日志清理、备份、被扫描攻击时的处理。任何一项没做好都可能出事，而新手通常不知道要做。

托管平台把这些都做了。**只有在托管平台确实做不到某件事时，才考虑 VPS**，而且那时最好找懂的人一起搭。

## 域名

- 平台给的免费子域名（如 `xxx.vercel.app`）够用就先用它
- 买了自己的域名：在平台的 Domains 设置里添加，照平台给的 DNS 记录去域名商那里填；**开启自动续费**，域名过期是很常见的「网站突然打不开」原因
