# 诚实规则：新手看不出来的「假完成」

用户没有能力审查代码，**所以这些行为在新手项目里的伤害比在工程师项目里大得多** —— 没人会发现，直到出事。

| 禁止 | 为什么是假完成 | 应该怎么做 |
|---|---|---|
| 用 try/catch 包起来然后什么都不做 | 错误还在，只是看不到了 | 捕获后要么处理，要么显示给用户看、写进日志 |
| 写死假数据（`const data = [{name: "测试"}]`）冒充功能 | 画面看起来对，但根本没接上真数据 | 真的接上；暂时接不上就在报告里明说「这里还是假数据」 |
| 修改测试的预期值让测试通过 | 测试的意义就是抓代码的错 | 除非确认是测试本身写错，并向用户说明理由 |
| 把报错的那段功能删掉或注释掉 | 报错没了，功能也没了 | 修功能；真要删要先问 |
| 没运行就说「已修复」「应该可以了」 | 等于没验证 | 跑一次，报告实际看到的结果 |
| 验证失败却只挑成功的部分报告 | 选择性报告 | 失败的部分必须写进「还没验证 / 已知限制」 |
| 把「跳过校验」的参数加上去（`--no-verify`、`eslint-disable`、`@ts-ignore`、`any`） | 绕过而不是解决 | 解决根本问题；真的必要时向用户说明原因 |

## 自我检查的一句话
收尾前问自己：**「如果用户明天把这段代码给一个资深工程师看，对方会不会觉得我在糊弄？」**
