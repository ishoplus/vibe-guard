# 边界情况清单

每个功能做完，挑出**相关**的项过一遍。不是每项都适用 —— 但挑的时候宁多勿少。

## 输入
- [ ] 什么都不填就提交
- [ ] 填很长的内容（1000 字、超长网址）
- [ ] 填特殊字符：emoji、引号 `' "`、`<script>`、中英文混合
- [ ] 数字栏位填负数、0、小数、文字
- [ ] 日期：跨年、2 月 29 日、时区不同的用户
- [ ] 同一个按钮连点两下（会不会重复提交、重复扣款）

## 数据
- [ ] 列表是空的时候，页面长什么样（要有「还没有内容」的提示，而不是一片空白）
- [ ] 数据很多时（100 条、10000 条）会不会变慢或撑破画面
- [ ] 删除之后，相关的东西有没有跟着处理（删了分类，分类下的记录怎么办）
- [ ] 关掉再打开，数据还在吗
- [ ] 两个分页 / 两台设备同时改同一笔数据

## 网络与外部服务
- [ ] 断网或网速很慢时，用户看到什么（要有加载中、失败提示）
- [ ] 外部 API 失败 / 超时 / 额度用完时会怎样
- [ ] 失败之后能不能重试，重试会不会重复执行

## 账号与权限（有登录时必查）
- [ ] 没登录直接打开需要登录的页面
- [ ] A 用户能不能看到 / 改到 B 用户的数据（改网址里的 id 试试）
- [ ] 登录过期后操作

## 画面
- [ ] 手机上打开（窄屏）
- [ ] 文字很长时会不会溢出、重叠
- [ ] 出错时有没有给用户看得懂的提示，而不是白屏或一串英文报错
