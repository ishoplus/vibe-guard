# 上线人工清单

自动脚本判断不了的部分。**按项目实际情况挑适用项**，不适用的直接跳过，不要逐条念给用户听。

## 1. 钱（每个项目都要）
- [ ] 所有付费服务都设了**预算上限或告警**（方法见 `../../safe-start/references/budget-alerts.md`）
- [ ] 调用 AI / 付费 API 的地方都经过后端，且有**每个用户、每天的次数上限**
- [ ] 没有「页面每次打开就调用一次付费 API」的写法
- [ ] 测试用的服务器、数据库、部署都已删除

## 2. 数据
- [ ] 数据库**自动备份**已开启，并且**实际恢复过一次**（没恢复过的备份不算备份）
- [ ] 知道改数据表结构的正确方式（migration），不会直接在正式数据库上手动改
- [ ] 测试数据已清掉，或和正式数据分开

## 3. 账号与权限（有登录时）
- [ ] 登录用现成服务（Supabase Auth、Firebase Auth、Clerk、Auth0 等），**没有自己存密码**
- [ ] 用账号 A 登录，改网址里的 id 或直接调用 API，**看不到、改不到账号 B 的数据**（请实际试一次）
- [ ] 没登录时打开需要登录的页面，会被挡住
- [ ] 管理员功能有额外的权限检查，不只是「前端不显示按钮」

## 4. 输入
- [ ] 所有用户输入**在后端再检查一次**（前端检查可以被绕过）
- [ ] 用户上传文件时限制了类型和大小
- [ ] 用户输入的内容显示到页面上时不会被当成代码执行（输入 `<script>alert(1)</script>` 试试）

## 5. 隐私
- [ ] 清楚自己存了哪些个人信息，只存必要的
- [ ] 给别人用、会收集个人信息的，有一份简单的隐私说明（收了什么、做什么用、怎么删除）
- [ ] 用户能删除自己的账号和数据
- [ ] 面向中国大陆用户的网站，了解是否需要 ICP 备案；面向欧盟用户，了解 GDPR 的基本要求

## 6. 出事时知道（细节见 deploy-guide 的监控与回滚、incident-rescue）
- [ ] 有错误监控（例如 Sentry），出错会通知你，而不是等用户来说
- [ ] 知道去哪里看线上日志
- [ ] 知道怎么**退回上一个版本**（多数托管平台有一键回滚，先找到按钮在哪）

## 7. 基本体验
- [ ] 正式网址是 HTTPS（网址前有锁）
- [ ] 手机上打开正常
- [ ] 出错时显示的是看得懂的提示，不是白屏或英文报错
- [ ] 本地的环境变量都已经在托管平台上设置好（上线后功能坏掉最常见的原因）
