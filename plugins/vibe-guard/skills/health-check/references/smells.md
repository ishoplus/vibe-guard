# 新手项目常见的「开始变乱」信号

| 信号 | 怎么发现 | 不整理的后果 | 整理方向 |
|---|---|---|---|
| 巨型文件 | 单文件超过 400 行；一个组件里有画面 + 存数据 + 调 API | 每次改动都牵一发动全身；AI 读不完整个文件就开始乱改 | 按「职责」拆：画面、数据存取、外部服务各自一处 |
| 同一件事多种写法 | 搜「fetch(」「supabase.from(」「localStorage」看出现在几个地方 | 改一处忘了另一处，bug 修不干净 | 统一成一个函数，其他地方都调它 |
| 复制粘贴的代码块 | 几段几乎一模一样的代码 | 修一个 bug 要修 N 次 | 抽成共用函数 |
| 残留调试代码 | 大量 console.log / print / debugger | 性能、泄露信息、日志噪音 | 删掉或换成正式日志 |
| 跳过检查 | `@ts-ignore`、`any`、`eslint-disable`、`# type: ignore`、空的 catch | 问题被藏起来，以后在奇怪的地方爆 | 逐个解决根本原因 |
| 写死的值 | 网址、价格、ID、密钥直接写在代码里 | 换环境就坏；密钥泄露 | 移到设置文件或环境变量 |
| 没有测试的核心流程 | 最重要的动作（付款、存数据、登录）没有任何自动检查 | 每次改动都可能悄悄弄坏它 | 至少给最重要的 1–3 个流程补测试 |
| 死代码 | 没人调用的函数、注释掉的大段代码、不用的文件 | 干扰 AI 判断，AI 可能去改错地方 | 删掉（git 里有历史，不怕） |
| 依赖膨胀 | 依赖数量远超功能需要；同功能装了两个库 | 安装慢、漏洞多、冲突多 | 移除不用的，同功能只留一个 |
| 说明书过期 | AGENTS.md / CLAUDE.md 写的结构 / 启动方式和现实不符 | AI 每次都按错的说明做事 | 更新说明书 |
