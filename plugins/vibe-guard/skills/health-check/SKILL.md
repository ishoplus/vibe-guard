# 项目体检

新手项目的崩坏是渐进的：每次加功能都「能跑」，但结构越来越乱，直到某天加什么都坏。体检的作用是**在崩之前让问题可见**，并且只挑最值得做的几件事。

## 执行流程

1. **跑体检脚本**：`python3 scripts/snapshot.py <项目根目录>`。输出项目规模、最大的文件、调试残留、跳过检查的写法、TODO、测试覆盖情况、依赖数量。
2. **人工看结构**：对照 `references/smells.md` 的清单，重点看：
   - 脚本列出的最大几个文件：是不是一个文件做了太多事
   - 同一件事是不是有多种写法（例：三个地方各自写了一遍存数据的逻辑）
   - AGENTS.md（或 CLAUDE.md）里写的项目结构，和实际还一不一致
3. **排优先级**：从所有发现里挑出**最该先整理的 3 件**。排序依据：
   - 会造成安全或数据问题的 > 会让下一个功能很难加的 > 只是不好看的
   - 用户接下来要做的功能会碰到的地方，优先
4. **写 HEALTH.md**（项目根目录，覆盖旧的）：照下面格式。session_start hook 会依据这个文件的更新时间来决定下次什么时候提醒体检。
5. **向用户报告**：只讲 3 件事，每件用四段说明：要整理什么 / 为什么现在该整理 / 整理之后加功能会变得怎样 / 不整理会怎样（多快会出问题），再加一句大概要多久。问用户要不要现在处理；要的话，每件事按 small-steps 流程做，**整理时不改功能**，整理完逐一验证功能没坏。
   每整理完一件，按平台复查一次：
   - **Claude Code**：调用 `simplify` 技能复查这次整理的改动（它会顺手修掉重复和绕远的写法）
   - **Codex**：调用内置的 `review-agent` 技能审查这次改动；或请用户输入 `/review`
6. **更新 AGENTS.md（或 CLAUDE.md）** 的项目结构一节，让它和现实一致。

## HEALTH.md 格式

```markdown
# 项目体检 {日期}

## 总体：🟢 健康 / 🟡 开始变乱 / 🔴 需要先整理再加功能
{一句话}

## 最该先做的 3 件事
1. **{问题}** —— 不整理会：{后果}。估计工作量：{小/中/大}
2. ...
3. ...

## 其他发现
- ...

## 数据
{贴上脚本输出的摘要}
```

## 资深模式
session 显示「资深模式」时：校验、检查、确认步骤一律照做，只省略教学性说明（白话类比、四段说明、术语解释）。本技能具体差异：
- 脚本和结构检查照做，HEALTH.md 照写（session 提醒依赖它）
- 报告列出全部发现，按优先级排序，每条一行（问题 / 影响 / 工作量）；不限于 3 件，不写教学说明
- 整理后的复查（simplify / review-agent）照做

## 硬性纪律
- 体检本身不改代码；整理必须经用户同意，并按 small-steps 一件一件做
- 整理（重构）前后功能必须一致 —— 整理前先记下要验证的功能清单，整理后逐一验证
- 不要列 20 条问题给新手看。只给 3 件，其余放「其他发现」
